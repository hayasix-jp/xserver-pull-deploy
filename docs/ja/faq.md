# FAQ と制限事項

## FAQ

**Q. エックスサーバー以外でも使えますか？**
A. サーバー側に必要なのは POSIX sh・curl・tar（gzip）・rsync・Cron（と、あれば flock・PHP）です。これらがそろった
共用サーバーなら動く可能性がありますが、動作確認はエックスサーバーを前提にしています。公開フォルダが `/public_html` で終わらない場合は `docrootSuffix` を設定してください。

**Q. PC を使わず、GitHub だけで運用できますか？**
A. 日常の公開はできます。ただし**最初の 1 回**（サーバー側スクリプトと `.htaccess` の記録を置く）と、`.htaccess` を
変えるときは PC からの `xpd deploy` が必要です。これは「サーバーの設定は GitHub からは変えられない」という安全上の
設計です。PC が海外回線しか無い場合は、国内の回線から一時的に実行してください。

**Q. 国外アクセス制限を OFF にする必要は本当に無いですか？**
A. ありません。プル型はサーバーから GitHub への外向きの HTTPS 通信だけを使います。

**Q. 反映までの時間は？**
A. push からビルド完了まではサイト次第（Actions の起動＋ビルド）。ビルド後は `kick.php` で数秒、`kick.php` が使えない
環境でも Cron の間隔（毎分なら 1 分以内）です。PC からの `xpd deploy` は 20〜30 秒程度です。

**Q. GitHub API の回数制限は大丈夫？**
A. 毎分 3 回の確認（ソースのブランチ・deploy・deploy-status）はすべて条件付きリクエストで、変化が無ければ 304 になり、
通常は回数制限に数えられません。公開のときだけ、ファイルを 3 つ取得します。

**Q. 1 つのサーバーに複数のサイトを置けますか？**
A. はい。`name` をサイトごとに変えてください（`~/.deploy/<name>` が分かれます）。Cron もサイトごとに 1 行。
トークンもリポジトリごとに分けます。

**Q. サブドメインのフォルダ（`public_html/sub/`）やアップロードしたファイルは消えませんか？**
A. 消えません。削除の対象は前回のデプロイで公開したファイルだけです（ログに「保護」と出ます）。**初回のデプロイは
何も削除しません**（同じ名前のファイルは上書きします。元の中身は `~/.deploy/<name>/original/` にも保存）。
ずっと残したいフォルダは `protect` に書いておくと確実です（デプロイがそのパスに書き込むこともなくなります）。

**Q. WordPress と同じ public_html に置けますか？**
A. おすすめしません。WordPress のファイルは消しませんが、サイトの `index.html` や `.htaccess` が WordPress の
`index.php`・`.htaccess` より優先されたり、上書きしたりします。別のドメインかサブドメインに分けてください。

**Q. 切り戻しはどこまでできますか？**
A. サーバーに保存している直近 `keep` 回分です（既定 5）。`xpd list` で確認できます。それより前の版は、Run workflow の
`ref` に古いコミットを指定（`overwrite` に✓）してビルドし直します。

**Q. 切り戻した後、次に push するとどうなりますか？**
A. 新しい内容が公開されます。切り戻しは「公開中のファイル」を戻すだけで、ソースはそのままです。取り消したい変更は
`git revert` してから公開してください。

**Q. ビルドに秘密の値（API キー）が必要です。**
A. GitHub の Secrets に登録し、ワークフローの `Build and bundle` ステップに `env:` で渡してください。サーバーには何も足しません。
ただし静的サイトに埋め込まれた値は公開されることに注意してください。

**Q. `deploy` ブランチの履歴が増え続けませんか？**
A. 毎回 orphan コミット 1 つで force push するので、ブランチには常に最新の 1 コミットだけです（古いコミットはそのうち GitHub が掃除します）。

**Q. Windows で使えますか？**
A. はい。PC 側は Node.js と ssh（Git for Windows 付属、または Windows 標準の OpenSSH）だけで動き、tar・rsync・bash は不要です。

**Q. テストはどう動いていますか？**
A. `npm test`。サーバー側のスクリプトを実際に sh で動かし、127.0.0.1 の偽 GitHub API と一時フォルダの偽 public_html を
相手にします。本物のサーバーや GitHub には一切接続しません。

## 制限事項

- **静的サイト専用**です。PHP・CGI など、サーバーで実行されるファイルはプル型では公開できません（PC からの `xpd deploy`
  では検査しないので置けますが、想定外の使い方です）。`.sh`・`.py`・`.pl`・`.rb` などのファイルを**配布したい**場合も拒否されます
  （拡張子を変えるか、zip にしてください）。
- **`.htaccess` の変更は PC から**しか公開できません（意図的な制限）。
- bundle（圧縮後）は **100 MB まで**（GitHub の Contents API の上限）。展開後の上限は既定 300 MB・20000 ファイル（`pull.env` で変更可）。
  大きな動画などは別の場所（ファイル管理での直接アップロード＋`protect`、または外部ストレージ）に置いてください。
- `public_html` 自体をシンボリックリンクで入れ替える方式ではなく、rsync の `--delay-updates` による入れ替えです。
  変更ファイルは最後にまとめて差し替えますが、数百ファイルの rename の間（通常 1 秒未満）にまたがったリクエストが
  新旧の混在を見る可能性はゼロではありません。
- ページ数ガードは `*.html` の数で判定します。HTML 以外が中心のサイトでは効果がありません。
- Cron の最短間隔は 1 分です（エックスサーバーのパネルの仕様）。
- kick.php は PHP の `exec` が使えない環境では何もしません（Cron が拾います）。
- サーバー側で flock が無い場合は mkdir によるロックになります（30 分で古いロックとみなします）。
- 状態表示の `token_expires_at` は GitHub が `GitHub-Authentication-Token-Expiration` ヘッダーを返すトークン（fine-grained / 期限付き classic）でのみ表示されます。
- サポートはベストエフォートです（[CONTRIBUTING.md](../../CONTRIBUTING.md)）。エックスサーバー社とは関係ありません。
